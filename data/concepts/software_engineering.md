# 소프트웨어 공학

## 결합도
- 빈도: 자주
- 정의: 모듈끼리 서로 얼마나 의존하는지. 낮을수록 좋음
- 약 → 강: 자료 < 스탬프 < 제어 < 외부 < 공통 < 내용
- 암기: 자스제외공내
- 자료: 값만 전달
- 스탬프: 자료구조(배열, 객체) 전달
- 제어: 제어 신호(플래그) 전달
- 외부: 외부에 선언된 데이터 참조
- 공통: 전역 변수 공유
- 내용: 다른 모듈 내부를 직접 참조

## 응집도
- 빈도: 자주
- 정의: 모듈 안 기능들이 얼마나 관련 있는지. 높을수록 좋음
- 강 → 약: 기능적 > 순차적 > 교환적 > 절차적 > 시간적 > 논리적 > 우연적
- 암기: 기순교절시논우
- 기능적: 하나의 기능만 수행
- 순차적: 앞 기능의 출력이 뒤 기능의 입력
- 교환(통신)적: 같은 입력·출력 사용
- 절차적: 정해진 순서대로 수행
- 시간적: 같은 시점에 실행
- 논리적: 비슷한 성격끼리 묶음
- 우연적: 서로 관련 없음

## 디자인 패턴 (생성·구조·행위)
- 빈도: 자주
- 생성 패턴 (5): 추상 팩토리, 빌더, 팩토리 메서드, 프로토타입, 싱글톤
- 구조 패턴 (7): 어댑터, 브리지, 컴포지트, 데코레이터, 퍼사드, 플라이웨이트, 프록시
- 행위 패턴 (11): 책임 연쇄, 커맨드, 인터프리터, 반복자, 중재자, 메멘토, 옵저버, 상태, 전략, 템플릿 메서드, 방문자
- 자주 나오는 패턴
  - 싱글톤: 객체를 하나만 생성
  - 어댑터: 맞지 않는 인터페이스를 맞춰 줌
  - 옵저버: 상태가 바뀌면 관련 객체에 알림
  - 프록시: 대리 객체가 대신 처리
  - 데코레이터: 기존 객체에 기능 덧붙이기

## 테스트 기법 (블랙박스·화이트박스)
- 빈도: 자주
- 화이트박스: 내부 코드를 보고 테스트
  - 기초 경로 검사
  - 제어 구조 검사 (조건, 루프, 데이터 흐름)
- 블랙박스: 입력·출력(기능)만 보고 테스트
  - 동등 분할: 입력을 그룹으로 나눠 대표값 사용
  - 경계값 분석: 경계 근처 값 사용
  - 원인-효과 그래프, 오류 예측, 비교 검사
- 테스트 단계: 단위 → 통합 → 시스템 → 인수

## 테스트 커버리지 (구문·결정·조건)
- 빈도: 가끔
- 구문(문장) 커버리지: 모든 문장을 1번 이상 실행
- 결정(분기) 커버리지: 조건문 전체 결과가 참·거짓 한 번씩
- 조건 커버리지: 개별 조건식이 참·거짓 한 번씩
- 조건/결정 커버리지: 위 두 개를 모두 만족
- MC/DC: 각 개별 조건이 전체 결과에 따로 영향을 주는지 확인
- 다중 조건 커버리지: 모든 조건 조합 확인

## UML 다이어그램
- 빈도: 가끔
- 구성 요소: 사물, 관계, 다이어그램
- 관계: 연관, 집합, 포함, 일반화, 의존, 실체화
- 일반화: 상속 관계 (빈 삼각형 화살표)
- 구조 다이어그램: 클래스, 객체, 컴포넌트, 배치, 복합 구조, 패키지
- 행위 다이어그램: 유스케이스, 시퀀스, 커뮤니케이션, 상태, 활동, 상호작용 개요, 타이밍

## 형상 관리
- 빈도: 가끔
- 정의: 소프트웨어 변경 사항을 추적·관리
- 절차: 형상 식별 → 형상 통제 → 형상 감사 → 형상 기록
- 도구: Git, SVN, CVS
